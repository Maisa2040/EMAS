# EMAS — نظام إدارة الخدمات الرقمية (نموذج أولي)

هذا مشروع ASP.NET Core MVC بلغة C# أُعدّ للفتح والتشغيل محلياً في Visual Studio. يتضمن بيانات توضيحية مصطنعة، ولا يتصل بقاعدة بيانات أو هوية مؤسسية.

## التقنية والمتطلبات

- .NET 10 LTS وC# 14.
- Visual Studio 2026 الإصدار 18.0 أو أحدث، مع تثبيت workload **ASP.NET and web development** و.NET 10 SDK.
- SQLite عبر EF Core؛ لا يلزم تثبيت SQL Server أو إعداد خادم قاعدة بيانات. أول تشغيل ينشئ `EMAS.Web/emas-demo.db` تلقائياً في وضع Development.
- اتصال إنترنت لأول مرة لاستعادة حزم NuGet.

> Visual Studio 2022 لا يوفر دعم الأدوات الكامل لاستهداف `net10.0`. استخدم Visual Studio 2026. المشروع يستخدم `net10.0` لأن هذا إصدار LTS الحالي وقت إعداد المشروع.

## التشغيل من Visual Studio

1. فك ضغط ملف المشروع إلى مجلد عادي.
2. افتح `EMAS.sln` في Visual Studio 2026. يمكن بدلاً من ذلك فتح `EMAS.Web/EMAS.Web.csproj`.
3. انتظر اكتمال **NuGet Restore**. إذا لم يحدث تلقائياً: انقر يميناً على الحل ثم **Restore NuGet Packages**.
4. من قائمة التشغيل اختر `EMAS.Web (HTTP)` للتشغيل المحلي دون إعداد شهادة HTTPS، أو `EMAS.Web (HTTPS)`.
5. اضغط **F5** للتشغيل مع المصحح، أو **Ctrl+F5** دون المصحح. يفتح المتصفح تلقائياً.
6. العنوان المحلي الافتراضي: `http://localhost:5080` (أو `https://localhost:7080`).

## التشغيل من الطرفية

داخل مجلد الحل:

```bash
dotnet --list-sdks
dotnet restore EMAS.sln
dotnet run --project EMAS.Web/EMAS.Web.csproj --launch-profile "EMAS.Web (HTTP)"
```

ثم افتح `http://localhost:5080`.

## حسابات العرض المحلية

| الدور | اسم الدخول | كلمة المرور |
|---|---|---|
| مدير النظام | `admin@emas.local` | `Admin123!` |
| مشرف | `manager@emas.local` | `Manager123!` |
| موظف | `staff@emas.local` | `Staff123!` |

هذه كلمات مرور ثابتة للعرض المحلي فقط؛ غيّرها أو احذف الحسابات الافتراضية قبل مشاركة أي نسخة. يوجد خيار لتغيير كلمة المرور من شريط أعلى الصفحة.

## ما يتضمنه النموذج

- تسجيل الدخول، قفل مؤقت بعد محاولات فاشلة، والأدوار Admin / Manager / Employee.
- لوحة متابعة تحسب الأعداد مباشرةً من قاعدة بيانات SQLite التجريبية.
- إدارة الموظفين والأقسام (التعطيل بدلاً من الحذف).
- إدارة المهام وإسناد المهمة إلى موظف أو أكثر، مع تحديث الحالة بحسب الصلاحية.
- تقديم طلب إجازة ومراجعته؛ مع منع تعارض الطلبات المعلقة/المعتمدة.
- مقترحات وشكاوى مع إخفاء الطلبات السرية عن المشرفين غير المخولين.
- سجل حضور يدوي للعرض فقط؛ لا يوجد تكامل جهاز/موارد بشرية.
- إدارة حسابات وأدوار محددة، تقارير وصفية وسجل تدقيق أساسي.
- واجهة عربية RTL متجاوبة دون الاعتماد على CDN أو مكتبات واجهة خارجية.

## إعادة ضبط بيانات التجربة

أوقف التطبيق، ثم احذف `EMAS.Web/emas-demo.db`. شغّل المشروع مجدداً في وضع `Development` وسيعيد إنشاء القاعدة والحسابات وبيانات المثال. **الحذف يمسح كل البيانات المحلية في هذا الملف.**

## حدود مهمة قبل أي استخدام حقيقي

- هذا نموذج أولي تعليمي/تشغيلي محلي، وليس نظاماً إنتاجياً معتمداً، ولا يحقق بحد ذاته متطلبات الأمن أو الامتثال الخاصة بالمؤسسة.
- لم يجر اختباره على شبكة المؤسسة، ولم يربط بالهوية المؤسسية أو SQL Server أو مصدر حضور رسمي. لا تضع بيانات حقيقية أو حساسة فيه.
- قائمة `AllowedHosts` متساهلة لتعمل معاينة التطوير؛ يجب ضبطها على أسماء المضيفين المعتمدة قبل أي نشر.
- يهيئ `EnsureCreated` مخططاً جديداً في Development لتسهيل البداية. قبل الإنتاج يلزم استبداله بمهاجرات EF Core وإجراءات ترحيل/نسخ احتياطي/استعادة معتمدة، ومراجعة أمنية وصلاحيات واحتفاظ بالبيانات.
- الأدوار والصلاحيات هنا تمهيدية؛ يجب اعتماد نطاق الوصول والتفويض المؤسسي واختباره على مستوى كل سجل.
- الأرصدة الرسمية للإجازات غير محتسبة، والحضور يدوي وليس مصدراً رسمياً، كما أن مؤشرات التقارير وصفية فقط.
- التكامل مع البريد، الملفات، إدارة الصلاحيات الديناميكية، تصدير PDF/Excel، والإشعارات الفعلية غير مفعلة في هذه النسخة.

## نقل قاعدة البيانات إلى SQL Server لاحقاً

يتطلب ذلك إضافة موفر `Microsoft.EntityFrameworkCore.SqlServer`، وضبط سلسلة اتصال آمنة خارج المستودع، واستبدال `UseSqlite` بـ`UseSqlServer`، وإنشاء migrations ومراجعة الترحيل والصلاحيات والنسخ الاحتياطي. لا تضع كلمات مرور قاعدة البيانات في `appsettings.json` أو Git.
